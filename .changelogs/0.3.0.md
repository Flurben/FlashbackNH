Much faster video exports. With vsync on, a 10-minute export took 113 s with a hardware encoder and about 200 s with x264, against 602 s in 0.2.1.

FlashbackNH is an unofficial, independent reimplementation of the feature set of Flashback. It is not affiliated with or endorsed by Flashback or its author.

## Faster exports

Measured on a 10-minute replay exported at 1920×1080, 60 fps, MP4, quality (CRF) 18, on an i7-13700K with an RTX 4070 Ti SUPER:

| | Export time | Speed |
|---|---|---|
| 0.2.1, vsync on | 601.6 s | 59.8 fps |
| 0.2.1, vsync off | 249.0 s | 145 fps |
| 0.3.0, x264 | about 200 s | 175–185 fps |
| 0.3.0, Auto (NVIDIA encoder) | 113.4 s | 318 fps |

The x264 time is worked out from 1-minute exports. Game memory now stays at the replay's level during an export instead of growing by several GB.

- **Vsync and frame limit off while exporting.** Before, an export with vsync on ran no faster than your monitor's refresh rate. The export now turns both off and restores them when it ends, is cancelled or fails. Your `options.txt` keeps your own values throughout.
- **Hardware video encoders.** A new *Encoder* button in the export dialog (MP4 and MKV). *Auto*, the default, uses your graphics card's or processor's video encoder if ffmpeg can use it, and x264 otherwise. You can also choose x264, NVENC H.264, NVENC HEVC, Intel QSV, AMD AMF or VideoToolbox. FlashbackNH checks which encoders work once per session by encoding a test frame with each. If the one you chose fails at the start of an export, the export uses x264 and tells you.
- **The same quality as before.** Each hardware encoder's quality setting follows the CRF field. For NVENC and Intel QSV it was measured against a lossless capture to look like x264 at the same CRF. Files from the NVIDIA H.264 encoder are about 30% larger than x264's for the same quality.
- **Frames are read from the graphics card without waiting for it**, so the next frame renders while the last one is copied. They are also read without the unused alpha channel, which is a quarter less data, and their memory is reused instead of allocated for every frame.
- **MP4 index setting.** *Standard*, the default, finishes the file at once and works in every player and editor. *Fragmented* also finishes at once and stays playable if the game crashes during an export, but some older editors read it badly. *Fast start (web)* is what 0.2.1 always did: ffmpeg rewrites the whole file at the end so it can play in a browser before it has fully downloaded.
- **PNG sequences** are written by all CPU cores but one, about 2.3 times faster. `pngCompression` in the config sets the compression level from 0 to 9 (default 4). The images are the same at every level.
- **Timing in the log.** After each export the game log shows where the time per frame went, so you can see what limits exports on your machine.

## Install

Put `flashbacknh-0.3.0.jar` in your `mods` folder. It is client only. Do not use the `-dev` or `-sources` jars.

## Known limits

- The AMD AMF and Apple VideoToolbox quality settings are estimates, not measured. If their files look worse or are much larger than x264's at the same CRF, choose x264.
- *Auto* never picks HEVC, because not every editor reads it. Choose NVENC HEVC yourself for smaller files.
- The x264 preset button only applies to x264, and it is greyed out when another encoder is in use.
- If exports show wrong or repeated frames with your graphics driver, set `asyncReadback=false` in the export section of the config.
- Export speed with shader packs and with Distant Horizons has not been measured since these changes.
- Everything listed for 0.2.1 still applies.

See the README for the full list of tested versions and limitations.
