Fixes for Forge Multipart microblocks and Server Utilities messages in replays.

FlashbackNH is an unofficial, independent reimplementation of the feature set of Flashback. It is not affiliated with or endorsed by Flashback or its author.

## Fixes

- **Missing microblocks.** Microblocks (pillars, covers, panels and other Forge Multipart parts) that were already in the world when a recording started mid-session were missing from the replay. Forge Multipart sends a chunk's microblocks in a packet of its own when a player first sees the chunk, and that packet came before the recording started. Recordings now include it. Replays recorded with earlier versions also show these microblocks now: they are rebuilt from the data the recording saved.
- **Replay closing when a microblock changes.** When a recorded player broke or changed one of those missing microblocks, Forge Multipart reported a "Client multipart ... not found" error and disconnected, which closed the replay. With the fix above this no longer happens. A replay also no longer closes on any disconnect message a mod sends during playback; it is logged and ignored.
- **Server messages in replays.** Server Utilities notifications, such as backup messages and entering or leaving claimed chunks, showed in replays even with chat hidden. They now follow the Chat setting in the Visuals panel, which is off by default.

## Install

Put `flashbacknh-0.2.1.jar` in your `mods` folder. It is client only. Do not use the `-dev` or `-sources` jars.

## Known limits

- Tested in singleplayer with pillar and face microblocks. Other multipart types (wires, pipes from other mods) use the same mechanism but were not tested, and neither was a server.
- Everything listed for 0.2.0 still applies.

See the README for the full list of tested versions and limitations.
